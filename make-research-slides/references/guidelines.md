# 研究発表・論文発表スライド作成ガイドライン（詳細版）

学会発表・論文発表・ゼミ発表用のスライドを作るときの全ルール。
スライドの目的は **装飾ではなく伝達**。「整理とバランス」を最優先し、足し算より引き算で作る。

---

## 0. 作業の進め方

1. **ヒアリング**（不明なものだけ聞く。分かっているものは聞かない）
   - 発表の種類：口頭発表 / ゼミ / 論文紹介（輪講）/ ポスター
   - 発表時間と質疑時間（例：発表12分＋質疑3分）
   - 学会名・聴衆（専門家中心か、専門外も多いか）
   - 言語（日本語 / 英語）、アスペクト比（既定 16:9。学会指定があれば従う）
   - 会場PCの環境と指定ファイル形式（PowerPoint のバージョン、PDF可否）
   - 素材：原稿・論文PDF・図・実験データの場所
2. **構成案（アウトライン）を先に出す**：各スライドの「タイトル＝主張文」と載せる図だけを一覧で示し、合意してから作る
3. **生成** → **レンダリングして目視QA**（§9）→ 修正
4. 成果物：`slides/<発表名>.pptx` と同名の `.pdf`（会場トラブル対策）、`slides/<発表名>_script.md`（発表原稿）

## 1. 構成（この順番を基本にする）

| # | セクション | 中身 | 10分発表の目安 |
|---|---|---|---|
| 0 | タイトル | 題目・発表者・所属・学会名・日付 | 1枚 |
| 0' | 本日の流れ | 発表の章立てを5項目程度で示す（§6.5） | 1枚 |
| 1 | 背景 | 一般的な話題 → 専門的な話題へ。「分かっていること」「まだ分かっていないこと」 | 1–2枚 |
| 1' | **先行研究** | 既存のアプローチを系統ごとに紹介し、それぞれの課題を示す → 本研究の位置づけ（§2.5） | 2–3枚 |
| 2 | 目的 | 背景の課題を解決する意義。**1文で言える目的** | 1枚 |
| 3 | 手法・提案 | 独自性と具体的な手順。システム構成図を必ず入れる。統計なら母集団の特性も | 2–3枚 |
| 4 | 実験・結果 | 実験条件 → 結果を図表・グラフ・写真・動画で可視化 | 2–3枚 |
| 5 | 考察 | 目的をどこまで満たしたか、分野での意義、限界 | 1枚 |
| 6 | まとめ・今後の課題 | 結果の要約と主張。限界点と今後 | 1枚 |
| 7 | 参考文献 | 本編で引用した文献の一覧（§2.5） | 1枚 |
| – | 予備スライド | 想定質問への回答用。本編の後ろに「Appendix」として置く | 任意 |

### 枚数
- 基本は **1分あたり1〜1.5枚**（10分なら本編10–15枚）。§2の「1スライド1情報」を守った結果、枚数が増えるのは構わない（1枚あたりの説明時間が短くなるだけで、聞き手の負担はむしろ減る）。
- 参考記事には「発表時間の1.5〜2倍の枚数」という目安もあるが、詰め込みすぎになりやすいので、リハーサルで時間を測って調整する。
- **予備スライドは枚数に数えない。**

### 入れないもの（原則）
- 謝辞スライド、研究グループ紹介、所属機関・プロジェクトの紹介（学会や助成元の指定がある場合を除く）
- 「本日の流れ」以外の目次（章ごとの細かい目次は不要。10分未満の発表では「本日の流れ」も省略可）
- スライドに載せきれない詳細 → **発表原稿（スピーカーノート）** と予備スライドへ

## 2. 1スライドの作り方

- **1スライド1メッセージ。** 言いたいことが2つあれば2枚に分ける。
- **強調は1スライドにつき1箇所だけ。**（最重要ルール）
  - **デザインの骨格と強調を分ける。**
    - 骨格（メインカラー）：スライドタイトル、見出し、番号の丸、カードの薄い塗り、図のブロック。全スライドで同じ使い方をするので、強調には数えない。見た目の完成度・プロらしさはここで出す。
    - 強調（アクセントカラー）：そのスライドで一番伝えたい1つの情報にだけ使う。必要なら大きい文字（24–40pt）・太字と組み合わせる。
  - アクセントカラーが2箇所以上に出てきたら、1つに絞るか、スライドを2枚に分ける。
  - 骨格は飾りを増やさない。1スライドの階層は「タイトル → 見出し → 本文」の3段まで。
  - 強調したいものが2つ出てきたら、スライドを2枚に分ける。
  - 表紙・本日の流れ・参考文献は、強調なし（0箇所）でよい。
  - 3秒テスト：スライドを3秒だけ見て、目が最初に止まる場所が「伝えたいこと」になっているか確認する。
- **スライドタイトルは「ラベル」ではなく「主張」を書く。**
  - ✕「実験結果」 ✕「提案手法」
  - ○「色マーカー検出はArUcoより遠距離で安定した」 ○「ステレオ視差から機体高度を直接推定する」
  - 長くなるので、タイトルは2行以内に収まるサイズ（§4）にする。末尾に句点「。」を付けない。
- **スライドは読むものではなく見るもの。** 図・表・写真を主役にし、文字は補足にする。
- 専門外の聴衆も想定し、専門用語は初出で一言説明する（例：「GNSS（衛星測位）」）。
- 結果スライドでは、グラフの見てほしい系列・箇所だけをアクセントカラーにし、他はグレーにする。説明文はグレーで1行だけ添える。

- **論文発表（大学生・大学院生の学会発表）を前提にする。**
  - 論文の章立て（はじめに → 関連研究 → 提案手法 → 実験 → 考察 → まとめ）とスライドの順番を対応させる。
  - 表紙に論文タイトル・著者（共著者・指導教員を含む）・所属・学会名を入れる。
  - 目的のスライドの近くに「本研究の貢献」を2〜3点で示す（論文の Contribution と一致させる）。
  - 手法は、聞き手が再現の見当をつけられる程度に具体的に書く（処理の手順、使ったライブラリ、主要パラメータ）。
  - 実験は「条件」「評価指標」「結果（数値の表）」「結果（グラフ）」を分けて見せる。
  - 論文の図表をそのまま貼らず、スライド用に文字を大きくして作り直す。

## 2.5 先行研究の扱い（必須）

先行研究は「背景」と「目的」の間に必ず入れる。目的の説得力は「先行研究では何ができていないか」で決まる。

### 構成（2–3枚）
1. **系統ごとに1枚**：既存のアプローチを2–3の系統に分け、1枚につき1系統。タイトルに「その系統の課題」を書く（例：「外部カメラ計測は高精度だが、設置が大がかり」）。強調するのはその課題1点。
2. **位置づけ（ポジショニング）を1枚**：比較カードまたは比較表（観点2–3個）で、先行研究と本研究を並べる。強調（アクセント）は本研究1点。2軸の図を使う場合は、軸と点の配置に根拠があるときだけにする。
3. その後に「目的」スライドを置き、先行研究の空白を埋めることを目的として述べる。

### 書き方
- 1本の論文を長々と説明しない。「何をした研究か」「何が課題か」を各1行で。
- 先行研究を否定する言い方は避け、「〜は得意だが、〜には向かない」のように、得意なことと課題をセットで書く。
- 比較表を使う場合は行（手法）を最大4つ、列（観点）を最大3つにする。○△×の記号を使い、本研究の行だけ強調する。

### 引用ルール
- 先行研究を載せたスライドには、左下に番号付きの引用を書く：`[1] 著者, 会議・論文誌名, 年`（12–14pt・グレー）。本文中では `[1]` の番号で参照する。
- 本編の最後に「参考文献」スライドを1枚置き、IEEE形式で一覧にする（14pt・グレー、強調なし）。
- **実在を確認した文献だけを載せる。** ユーザーの論文・原稿の参考文献リストから取るか、検索してDOI・書誌情報を確認したものに限る。確認できないものは `[要記入]` のプレースホルダーにする。著者名・年・タイトルを推測で書かない。
- 他者の図を引用する場合は、図の直下に出典番号を付ける。

## 3. 文章の書き方

- **情報量と見やすさのバランス。** 論文発表では、聴衆が手法・条件・結果を判断するのに必要な情報（手順、パラメータ、実験条件、評価指標、数値）は省かずに載せる。
  - 目安：本文は最大5項目、各項目は1〜2行。図があるスライドは、図の横に3〜4項目まで。
  - それを超えるときはスライドを分ける。細かい数値・導出は表や予備スライドへ。
  - 情報が増えても、強調（アクセントカラー）は1箇所だけ（§2）。他は通常の本文書式で淡々と並べる。
- 不自然にならない範囲で **助詞を削る**。**体言止め** を使ってよい（ただし多用しすぎない）。
  - 例：「ドローンの高度をステレオカメラによって計測する」→「ステレオカメラで機体高度を計測」
- 漢字が詰まって見えるときは、意図的に **ひらがな** にする（「選ぶ」→「えらぶ」「控える」→「ひかえる」）。
- 文章だけが続くスライドは作らない。表・図形・フロー図に置き換える。
- 数値は単位と条件を必ず書く（例：「n=10試行、高度0.5 m」）。**データにない数値・誇張した数値は書かない。** 未確定の値は `[要確認]` と明記する。

## 4. フォントと文字サイズ

- **ゴシック体を使う。明朝体は使わない**（線が細く、遠くから読みにくい）。
- フォントはスライド全体で統一する。既定：
  - 和文：**メイリオ（Meiryo）**（Windows・Mac版Office の両方で使える。会場PCがWindowsでも崩れにくい）
  - 代替：BIZ UDPゴシック / Noto Sans JP / ヒラギノ角ゴシック（Mac環境のみで発表する場合）
  - 欧文を分けたい場合：Arial または Segoe UI（会場PCに入っているか確認）
- 文字サイズ（**本文18pt未満は使わない**。出典・図の注記・ページ番号のみ例外）

| 要素 | サイズ | 太さ |
|---|---|---|
| 表紙の題目 | 32–36pt | Bold・メイン色 |
| スライドタイトル（主張文） | 24pt | Bold・メイン色（全スライド共通） |
| 見出し・番号 | 20pt | Bold・メイン色 |
| 強調する1箇所 | 24–40pt | Bold・アクセント色 |
| 本文・図のラベル | 18pt（最小） | Regular・本文色 |
| 出典・注記・ページ番号 | 12–14pt | Regular・グレー |

- 強調は「大きくする」だけでなく、**強調しない部分を小さく・薄くする** ことでも行う。

## 5. 配色

- 背景は **白（#FFFFFF）** か、ごく薄いグレー。色付き背景は目が疲れ、写真・グラフも映えない。
- 文字は純黒ではなく **濃いグレー #3C3C3C**（コントラストを少し下げて目に優しく）。
- **白黒（グレースケール）を基調にし、色は強調の緑1色だけ** にする。比率の目安：
  - ベース（本文の文字色）70%：濃いグレー `#3C3C3C`
  - メイン 25%：ほぼ黒 `#262626` とグレーの明度違い。タイトル・見出し・番号・表のヘッダー・カードの薄い塗りなど **デザインの骨格** に使う
  - アクセント 5%：緑 `#1F8A4C`。**1スライド1箇所の強調専用**。他の用途に使わない
- 緑は彩度を抑えた落ち着いた色にする（蛍光色のような明るい緑は使わない）。白背景で文字として読める濃さを保つ。
- 彩度・明度の高い色を本文に使わない。アクセントカラーが薄すぎて見えない、ということがないようにする。
- 既定パレット（発表ごとに変えてよいが、1発表の中では固定）

```
TEXT      = 3C3C3C   # 本文
SUB       = 7A7A7A   # 補足・注記・軸ラベル
LINE      = D9D9D9   # 罫線・グリッド
BG_SOFT   = F5F5F5   # 図の背景・カード
MAIN      = 262626   # メイン（ほぼ黒）
MAIN_TINT = EBEBEB   # メインの明るい版（薄いグレー）
GRAY2     = BDBDBD   # 比較系列・非アクティブ
ACCENT    = 1F8A4C   # アクセント（緑）
```

- 色だけで意味を区別しない（線種・マーカー形・ラベルも併用）。

## 6. レイアウト

- **視線は左→右、上→下。** その流れに沿って配置し、矢印で無理に誘導しない。
- 同じ重みの要素が複数ある場合は、同じサイズで並べる（4つなら2×2をZ字/N字で読む順に）。
- 要素は枠線で囲むより、**等間隔に並べて余白でまとまりを見せる**。
- 余白を先に確保してから整列する。左右の余白は最低 0.5インチ、要素間は 0.3インチ（または0.5インチ）で統一。
- オブジェクトの位置を揃える（左端・上端・中心）。同種のグラフは **大きさと位置を統一** する。
- タイトルの位置・サイズは全スライド共通。本文は左揃え（中央揃えはタイトルのみ）。
- ページ番号を右下に入れる（質疑で「◯ページの図」と言ってもらえる）。
- やらないこと：タイトル下の装飾ライン、画面端の帯・ストライプ、意味のないアイコン・クリップアート、影・3D・グラデーションの多用。

## 6.5 デザインの細部

- **余白でグループを示す。** 関係のあるものは近づけ、関係のないものは離す。見出し→本文の余白は、本文→次の見出しの余白より必ず小さくする。敷いた面（カード）と中身の間にも余白を取り、面いっぱいに詰めない。
- **「囲む」より「敷く」。** 線の枠は増えるほど雑多に見える。まとまりは薄い面（BG_SOFT / MAIN_TINT）を敷いて示し、枠線は使わない。図のプレースホルダーも枠線なしの面にする。
- **表は罫線を減らす。** 縦線は引かず、行の下に細い横線だけ。行や列の区別は色を敷いて示す。比較表では本研究の列（行）に薄いメイン色を敷き、関係を示す。
- **行を長くしない。** 文章を横幅いっぱいに置かず、1行はおおむね30字以内。長い「ですます」文は箇条書きにする。
- **装飾でコントラストを下げない。** 文字に影・下線・袋文字を付けない。色付きの面に白文字を置くときは、面の色を十分濃くする。
- **フォントは「声」。** 1発表で1書体に絞る。強調は書体を変えず、サイズ・太さ・色で行う。
- **色数は目的で決める。** 関連を示したいものは同じ色にそろえ、並列に見せたいもの（表など）は単色でまとめる。
- **本日の流れ（目次）を表紙の次に置く。** 章を5項目程度にまとめ、聞き手と話のゴールを共有する。
- **章ナビ。** 本編スライドのフッターに章の一覧を小さく（12pt）並べ、今の章だけメイン色・太字にする。聞き手が今どこにいるか分かる。
- **表紙に装飾は入れない。** 題目・著者・所属・学会名・日付だけを、余白を十分に取って左揃えで置く。
- **投影用と配布用。** 投影用は1枚の情報を絞る。配布資料も兼ねる場合は、A4に印刷して読めるか確認し、PDFは圧縮して軽くする。
- **実寸で確認する。** プロジェクタだけでなく、ノートPC・タブレット・印刷でも読めるかを見る。

## 7. 図表

- グラフ・図表・写真を積極的に使う。結果は可能な限りグラフで見せる。動画やシミュレーションも有効（PDF版には静止画を入れる）。
- グラフは PowerPoint ネイティブのグラフで作る（後から数値修正できるように）。軸ラベルに単位を必ず付ける。
- 凡例はできるだけ線の近くに直接ラベルとして置く。
- 1枚のグラフで伝えたい点は1つ。そこだけアクセントカラー、他はすべてグレー。
- システム構成図は「入力 → 処理 → 出力」が左から右に流れるように描く。
- 他者の図を引用する場合は、出典を図の直下に12–14ptで書く。
- **アイコンは、分かりやすくなる場所にだけ使う。** 目安は1発表で1〜2枚。
  - 使う場所：システム構成図・処理の流れなど、「モノ」や「処理」のブロックを並べる図（例：カメラ → 計算機 → 送信機 → 機体）。アイコンがあると何のブロックかがひと目で分かる。
  - 使わない場所：見出しの横、本日の流れ、背景・考察・まとめのカード、表紙。飾りになるだけなので、番号の丸や余白で整理する。
  - 種類：PowerPoint の「アイコン」に近い、線だけのシンプルなもの（例：Tabler Icons）。色はメインカラー1色で、強調する箱の中だけ白。同じ図の中では大きさをそろえる。
- まだ図がない場合は、枠線なしの薄いグレーの面に `[図：○○の写真に差し替え]` と書いたプレースホルダーを置く。

## 8. 実装ルール（pptx 生成）

- `pptxgenjs` のスクリプト `slides/build_<発表名>.js` で生成する（再生成できるように手作業の編集はしない）。ひな形は `assets/build_template.js`。
- `pres.layout = "LAYOUT_16x9"`（10 × 5.625インチ）。学会指定が4:3なら `LAYOUT_4x3`。
- テーマ（フォント・色）を最初に定義し、レイアウト（スライドマスター）を用意する：
  - `TITLE`（表紙）／ `SECTION`（区切り・任意）／ `CONTENT`（タイトル＋自由配置）／ `APPENDIX`（予備）
  - ページ番号・発表者名などのフッターはレイアウト側に置く。
- `pres.addSection()` で §1 の構成に沿ったセクションを付ける。
- 各スライドに **スピーカーノート（発表原稿）** を `slide.addNotes()` で入れる。目安は1枚あたり150–250字（日本語は1分で約300字）。
- 色の指定は `#` なしの6桁HEX。
- アイコンは `react-icons` の SVG を `sharp` で PNG（512px）にしてから `addImage()` で貼る（ひな形の `preloadIcons()` / `icon()` / `iconBadge()`）。
- **日本語の字形を必ず日本語にする。** pptxgenjs は文字を `lang="en-US"`・中国語の文字セット（`charset="-122"`）で書き出し、テーマの東アジア用フォントも空欄になる。このままだと環境によって漢字が中国語の字形で表示される。書き出し後に、全XMLで `lang` を `ja-JP`、`charset="-122"` を `"-128"`、空の `<a:ea typeface="">` を使用フォントに置き換える（ひな形の `fixJapanese()`）。
- PDF にしたら `pdffonts` で使われたフォントを確認し、中国語用フォント（例：`NotoSansCJKsc`）が混ざっていないことを確かめる。
- 生成後に PDF に変換し、全ページを画像にして確認する。

## 9. 完成前チェックリスト

**内容**
- [ ] 目的を1文で言える。背景 → 先行研究 → 目的 → 手法 → 結果 → 考察 → まとめ の流れになっている
- [ ] 先行研究の課題と本研究の位置づけが示され、目的がその空白を埋める形になっている
- [ ] 引用番号と参考文献スライドが対応している。すべての文献が実在・書誌情報確認済み
- [ ] すべてのタイトルが「主張文」になっている。タイトルだけ順に読むと話の筋が通る
- [ ] 1スライド1メッセージ。結果スライドに「見てほしい点」が示されている
- [ ] **アクセントカラーの強調が各スライド1箇所だけ**。骨格（メインカラー）は全スライドで同じ使い方
- [ ] 本文は最大5項目・各1〜2行。情報は十分だが、3秒見て伝えたいこと（強調箇所）が分かる
- [ ] 専門用語を初出で説明している。数値に単位・条件がある。根拠のない数値がない
- [ ] まとめで限界と今後の課題に触れている。想定質問と予備スライドがある

**見た目**
- [ ] 本文18pt以上、ゴシック体、フォント統一。漢字が中国語の字形になっていない
- [ ] 白黒基調で、色は強調の緑だけ。背景は白
- [ ] 文字のはみ出し・重なりがない。要素が整列し、余白が揃っている
- [ ] 同種のグラフの大きさ・位置・軸ラベルの書式が揃っている
- [ ] ページ番号と章ナビがある。表紙の次に「本日の流れ」がある
- [ ] 枠線より面を敷いてまとめている。表は横線のみ。見出しと本文の余白が、グループ間の余白より小さい
- [ ] 文字に影・下線がない。横幅いっぱいの長い行がない
- [ ] アイコンは構成図など必要な場所（1〜2枚）だけ。飾りのアイコンがない

**発表準備**
- [ ] 学会指定のファイル形式・アスペクト比・ソフトのバージョンを確認した。PDF版も用意した
- [ ] リハーサルで時間を測った（録画して見直すとよい）
- [ ] 第三者（研究室のメンバー・指導教員）に見てもらった
- [ ] スライド作りに時間をかけすぎていない（内容と練習に時間を回す）
