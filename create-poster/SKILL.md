# Research Poster Skill（学会ポスター作成ガイド）

どの研究でも「ぱっと見で一番言いたいことが分かる」学会ポスターを作るための手順とルール。
新しいポスターを作るときは、このファイルを渡して「この Skill に従って作って」と依頼する。

---

## 0. 作り始める前に必ず確認すること

作る前に、次の項目を研究者に確認する。分からない項目は空欄のままにし、勝手に作らない。

| 項目                            | 例                                         |
| ------------------------------- | ------------------------------------------ |
| 学会名・サイズ・向き            | GCCE 2026 / A0 縦 (841 × 1189 mm)          |
| 一番言いたいこと（主役）を1文で | 構造情報を足しても修復の成功は増えなかった |
| 主役の根拠となる数字            | 50/103 (48.5%) vs 45/103 (43.7%)           |
| 補足の結果                      | コンパイル失敗は CFG/PDG が最少            |
| 解釈・考察（未検証のもの）      | 既存の構造を保つパッチを促したかもしれない |
| 動機（なぜやるのか）            | LLM は依存先の修正を見落とす               |
| 比較する条件                    | Basic / +AST / +CFG/PDG                    |
| データセットと出典              | Defects4J [1]                              |
| 例として使えるコード・図        | 実験の条件を満たす短い例                   |

**最初に「主張の3層表」を研究者と一緒に作る。** これがポスター全体の設計図になる。

| 層             | 内容                   | 根拠         | ポスター上の扱い                         |
| -------------- | ---------------------- | ------------ | ---------------------------------------- |
| 主役           | 一番言いたい結果       | 数字         | 最大の文字・強調色・結果セクションの先頭 |
| 補足           | 主役を支える・補う結果 | 数字         | グラフ横の 35% 枠、中くらいの文字        |
| 解釈（可能性） | 未検証の考察           | 定性的な観察 | 「possible · not yet verified」と明記    |

---

## 1. 構成：上から下へ一本の流れ

縦長ポスターは、上から下へ読むだけで話が分かる構成にする。左右に行き来させない。

```
Title（タイトル・著者・所属）
 1. Question / Motivation   なぜやるのか・何を問うのか
 2. Experiment              何と何を比べたのか
 3. Results                 ★主役はここ（Main Finding）
 4. Interpretation          考えられる理由（未検証なら明記）
 Conclusion                 強調色の箱で1〜2文
 References                 小さく
```

- セクションには丸の中に番号（1, 2, 3…）を付け、ラベル（QUESTION / RESULTS など）を等幅フォントで添える。
- **Main Finding はタイトルの直下に置かない。** 結果セクション（3.）の先頭に置く。結果を読む流れの中で一番大きく見せると、根拠の数字と主張が隣り合って一目で分かる。

---

## 2. 一番言いたいこと（主役）の見せ方

主役が一目で分かることが最優先。

- 結果セクションの先頭に、**主張の一文と、それを示す数字を横に並べた大きな箱**を置く。
  - 左側：「MAIN FINDING」ラベルと主張の一文（1〜2行）。
  - 右側：比較する数字を2つだけ大きく（例：Basic 48.5% ／ +CFG/PDG 43.7%）。
- 主張の一文は **1〜2行に収める**。3行以上になる場合は文を短くする。
- 主張の中のキーワード（例：「did not increase」）だけを強調色にする。
- **強調色の箱はポスター全体で主役だけに使う。** 他の箱が同じ色だと主役が埋もれる。
  - 箱の色がグラフの条件色（例：Basic のネイビー）と同じ場合は、薄い強調色の背景と強調色の枠に変える。
- 主役の下にグラフを置く。主要な結果 65%、補足 35% で横に分け、間に細い縦線を入れる。

---

## 3. 動機（1. Question）の書き方

- 見出しは「何を扱うか」ではなく**「なぜやるのか」が分かる問いの形**にする。
  - ✗ Which structural context helps LLM-based repair?
  - ✓ LLMs may fix the buggy line but miss dependent code. **Can CFG/PDG show them what else to change?**
- 合わせて2文・20語程度。2文目（問い）を強調色にする。
- KEY POINT の帯には、動機を1文で書く（例：Fixing only the buggy line is not enough — dependent code must change too.）。
- 「思想」（人間の頭の中のイメージをコンピュータに落とし込む、など）による研究の位置づけは**ポスターに書かず、口頭で話す**。説明の文は事前に用意しておく。
- 要確認の数字（例：複数箇所の修正が必要なバグは何件か）は、確認するまでポスターに載せない。

---

## 4. 例（Toy example）の選び方と描き方

例は実験の主張を体現していなければ意味がない。

**選ぶ条件（すべて満たすこと）**

1. 本物のバグ・本物の現象であること。
2. 研究の主張を表していること（例：1か所直すだけでは足りず、依存先も直す必要がある）。
3. 短いこと（4〜6行程度）。

**描き方**

- バグの行に赤い枠・波線を付け、「BUG: 〇〇」のラベルを置く。
- 一緒に直す必要がある箇所は**別の色**（例：オレンジ）の塗りで示す。説明はコードの下に1行だけ（例：`int` → long: must also change）。
- **注釈は最小限にする。** 矢印・タグ・補足文を何個も足すとかえって分かりづらくなる。1つのコードに付ける注釈は「バグ」と「一緒に直す箇所」の2つまでにする。
- 図（AST / CFG / PDG など）は例と同じコードで描き、バグのノードを同じ赤で示す。
- 図の大きさで情報量の差を表したい場合は、意図的にその長さで描く（例：AST のトークン数が多いことをバーの長さで示す）。

---

## 5. KEY POINT の帯

- 各セクションに**1つだけ**置く。薄い背景色の帯に「KEY POINT」ラベルと太字の1文。
- KEY POINT に書くのは**そのセクションの核となる考え**だけ。
  - **条件設計の理由**（例：AST を外した理由）は KEY POINT にしない。図の下に小さな注記として書く。
  - その条件で確かめていないこと（例：AST を外した効果）を、主張のように書かない。
- 実験セクションの KEY POINT は「この比較で 1. の問いを確かめる」という位置づけの説明に使う。その際、1. の問いの言葉と揃える（1. に戻らなくても意味が分かるようにする）。

---

## 6. グラフ・結果の見せ方

- **どちらが良いかを必ず示す。** 軸の上に矢印と「More fixed = Better」「Fewer = Better」のラベルを付ける。
- 一番良い条件に「BEST」のラベルと緑の枠を付ける。
- 値は大きな数字で書き、割合を横に添える（例：50　48.5%）。
- 条件名はポスター全体で統一する（例：Basic / Basic + AST / Basic + CFG/PDG）。
- 補足グラフの下に、そのグラフの結論を1文で書く。

---

## 7. 確かさの度合いを書き分ける

| 確かさ               | 書き方                                                                             |
| -------------------- | ---------------------------------------------------------------------------------- |
| データで示した結果   | 断定する（did not increase / had the fewest）                                      |
| 未検証の解釈         | may / possibly / Potential と書き、「possible · not yet verified」のバッジを付ける |
| トレードオフなど推測 | 「Potential trade-off:」のように書き始める                                         |

結論でも、未検証の部分は断定しない。

---

## 8. 色のルール

色を使いすぎてチカチカさせない。役割ごとに決め、全体で使い回す。

| 役割                         | 例               |
| ---------------------------- | ---------------- |
| 文字・見出し・基本条件       | ネイビー #1d2b4f |
| 比較条件 A                   | 水色 #6fc0ea     |
| 比較条件 B・主役の強調       | オレンジ #e0532b |
| バグ                         | 赤 #c62828       |
| 「良い」の表示（BEST・矢印） | 緑               |
| KEY POINT の帯               | 薄い青 #e8eef8   |
| 結論の箱                     | 紫               |

- 条件の色は、図・プロンプトの図・グラフ・本文ですべて同じにする。
- 新しい色を足す前に、既存の色で表せないか考える。
- 本文の文字と背景のコントラストを十分に取る（薄い文字を使わない）。

## 9. 文字サイズと余白（A0 縦）

| 要素             | サイズ                           |
| ---------------- | -------------------------------- |
| タイトル         | 110〜130px                       |
| 主役の一文       | 84〜112px                        |
| セクション見出し | 76〜88px                         |
| KEY POINT の文   | 52px                             |
| 本文             | 42px 以上                        |
| 注記・凡例       | 28〜34px（これより小さくしない） |
| コード           | 30〜40px                         |

- 2〜3 m 離れても読めることを基準にする。
- 主張の一文・KEY POINT は1〜2行で収まりよく。不自然に1語だけ次の行に落ちる場合は、文を短くするか文字サイズを調整する。

---

## 10. 1ページに収める

- ポスターは必ず1ページ（A0）に収める。はみ出したら、次の順に調整する。
  1. 文を短くする（特に KEY POINT・主張）。
  2. セクション間・箱の内側の余白を詰める。
  3. 図の枠の高さを少し下げる。
  4. 最後に文字サイズを少し下げる（上の表の最小値は守る）。
- 図を小さくしすぎて見えなくならないようにする。
- 修正のたびに、コードや文字が枠からはみ出していないか確認する。

---

## 11. 参考文献

- 本文中で参照する箇所に [1] を付け、下部に小さくまとめる。
- データセット・ベースライン手法など、ポスターで使ったものの出典は必ず載せる。
